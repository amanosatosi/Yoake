# Aegisub 3.5 Automation continuation

The user supplied `C:\aegisub source\Aegisub-3.5.1` as the reference. Its Automation Lua and MoonScript includes and autoload sources are copied to `automation-3.5-above`, with per-file hashes and provenance in `third_party/automation/aegisub-3.5.1-provenance.json`. The templater and Karaskel have documented hooks for the unmodified Toshi-ban Mangetsu adapter. Existing `automation` sources and their Mangetsu adapter are retained. The archive is not assumed to have a Git identity.

Scripts whose master path is under the installed or user `automation-3.5-above` roots prefer that profile's user and packaged include directories before other configured includes. Within that profile, `?user/automation` and `?data/automation` resolve to the corresponding `automation-3.5-above` directories, including paths requested by package managers; similarly named paths are not rewritten. Legacy scripts retain their original token mappings. The default autoload search additionally scans the user profile's `automation-3.5-above/autoload`; the packaged 3.5 autoload examples are not automatically registered alongside their 3.2.2 counterparts, to avoid duplicate macros. Existing custom autoload preferences remain authoritative. The separate tree is packaged with Windows releases.

The shared host now provides `subs.script_resolution()`, as 3.5.1 Karaskel requires. It reads the captured subtitle document's resolution and uses the established Aegisub resolution fallback, with expired subtitle object checks. Real Lua regression coverage invokes the 3.5.1 templater with the adapter hook and checks effects and undo. These changes are a compatibility checkpoint, not proof that every 3.5.1 script works.

**DependencyControl is not yet installed or supported.** The upstream project needs more than an include directory: its loader, updater, configuration and dependent native/Lua modules must be audited, pinned and tested against the 3.5 host contracts and the requested separate user data paths. The user fork's pinned DependencyControl v0.9.0 (commit `8cd732eae9cb83de06b1ace6da210423827289f2`) requires LuaJIT's Lua 5.2 compatibility mode and MoonScript 0.3.0 or later; Yoake's existing 3.2.2 runtime uses 5.1 semantics. Other 3.5 host API differences remain to be audited. No duplicate or placeholder dependency manager is exposed.
