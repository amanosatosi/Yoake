Inspected implementations and called helpers:

- `src/command/video.cpp`: `validator_video_loaded`, `validator_video_attached`, `video_zoom_50/100/200`, `video_zoom_in/out`, `video_reset_pan`, `video_detach`, and `init_video`. Presets set window zoom to .5/1/2 and stop playback. In/out add/subtract .125 without stopping. All five require attached Video. Reset requires loaded Video and calls `ResetContentZoom`; Detach is a loaded-Video toggle.
- `src/video_display.h/.cpp`: constructor, `SetWindowZoom`, `FitClientSizeToVideo`, `UpdateViewportSize`, `PositionVideo`, `OnSizeEvent`, `OnMouseEvent`, `Pan`, `OnMouseWheel`, `GetZoomAnchorPoint`, `ZoomAndPan`, `ResetContentZoom`, zoom combo handlers, DPI handler, `SetTool`, `GetMousePosition`, destructor. Window zoom is physical display height / decoded source height, with width corrected by selected aspect. It is clamped to .125–10. It is NOT fit-to-window. A separate content zoom defaults to 1. Middle drag adds physical pan; pan is bounded by half content size + 40% viewport size on each axis, even when the image fits. No special middle-drag cursor is installed: normal visual-tool cursor remains. Reset clears pan AND content zoom, leaving window zoom/aspect.
- Default wheel actions in `src/libresrc/default_config.json` and enum in `video_display.cpp`: wheel changes window zoom by .125 per notch; Ctrl-wheel multiplies content zoom by 1 + .125 * notches around pointer; Shift-wheel pans 5 logical pixels per notch. Ctrl+Shift does nothing. Content zoom clamps .125–10. Viewport changes for window zoom/aspect rescale both pan axes by viewport-height ratio. Detached resize updates fitted window zoom; with active content zoom/pan it preserves absolute content height and pan.
- `src/visual_tool.cpp`: `OnMouseEvent` starts edits only on left clicks and captures left drags. `PositionVideo` passes the SAME display rectangle to `SetDisplayArea`; script mapping and rendering use it. Middle pan is not a subtitle edit.
- `src/video_controller.cpp`: `JumpToFrame` used during display creation/reattachment stops and resumes active playback around the current-frame request. Yoake preserves its single running clock while moving the existing controls, avoiding a restart while retaining the same visible playback continuity. `VisualToolBase::SetDisplayArea` cancels captured tool input when the rectangle changes; Yoake rolls back the corresponding transaction.
- `src/video_box.cpp`: `VideoBox` constructs the display, primary/subtool toolbars, slider, playback toolbar and editable zoom dropdown. Choices are 12.5–300% in 12.5-point increments; typed zoom may reach 1000%.
- `src/dialog_detached_video.cpp/.h`: constructor unloads old display and creates a NEW `VideoBox` using the same project/controller/selection context. It has full visual tools and hotkey handling, native resize/maximize/minimize, remembered location and title. `OnClose` destroys detached display, restores old display/slider, disables detached preference, requests current frame; it never closes media. `OnVideoOpen` updates title; Video Close closes the host but retains detached preference for a later reopen.
- `src/frame_main.cpp`: `OnVideoOpen` reduces initial zoom by .25 or .5 for oversized media, restores detached preference; `OnVideoDetach` hides/reveals embedded Video. `src/libresrc/default_menu.json` exposes Set Zoom, Detach and Reset Pan, including Video context menu. `src/libresrc/default_hotkey.json` binds Default Ctrl-KP_Add/Subtract and routes detached keys through Video Display. `src/persist_location.cpp` owns native location restoration.
