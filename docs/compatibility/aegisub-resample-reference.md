# Resolution resampling source audit — research only

No resample implementation or parity promotion is claimed here. Checkpoint 3 must pass before Checkpoint 4 is implemented.

Read-only primary Aegisub 3.5 archive: `src/command/tool.cpp` (`tool_resampleres`, stops video then opens dialog), `src/dialog_resample.cpp` (script/video resolution defaults, 1–999999 dimensions, Stretch/Add borders/Remove borders/Manual, symmetric margin controls, 1% aspect threshold), `src/resolution_resampler.h`, `src/resolution_resampler.cpp`, `src/ass_override.cpp` and `src/ass_file.cpp` (missing PlayRes fallback and explicit LayoutRes). No dedicated resolution-resampler test file exists in the supplied 3.5 test directory; existing YCbCr tests concern its separately optional color conversion. The requested Yoake workflow must preserve unrelated color and matrix settings.

The algorithm adjusts input margins for border/aspect policy, then computes independent rx/ry and a horizontal text stretch. Absolute positions use the corresponding margin plus axis scale; absolute sizes omit margins. Relative fscx uses horizontal stretch, while fscy stays unchanged. Font size, spacing, ordinary border/shadow and vertical variants use ry; xbord/xshad use rx. Inline blur and be are unchanged. Drawing-mode geometry scales x by rx/stretch and y by ry, while clip drawings use rx/ry. Style margins scale even when zero; event zero margins stay inherited. Code/template comment events are excluded. Integer parameters use the source's rounding contract. Explicit LayoutRes follows the supplied source formula, including its source-width divisor for vertical border adjustment; it must not be silently replaced with a guessed formula. Missing LayoutRes stays missing. Preserve source times, tags and non-geometric values.

Renderer oracle for extensions: `amanosatosi/libassmod` mangetsu branch observed at `78ad0541ee99cf79ef6d7cb0b6da57438a87eb83`; fetched `libass/ass_parse.c` blob `4b43f2dcf0222779b1935c8c6deb0ba8f568a532`. Inspected strict numeric/relative operands, positional Y direction, clip rectangle/vector argument parsing, clippos/clips, boxpx/boxpy/boxp/boxr and positioned gradient dispatch. Toshi-ban `src/ass_override.cpp` and `src/resolution_resampler.cpp` provide additional classifications, not permission to replace the renderer oracle.

Critical result: Mangetsu distort corners are normalized local corner pins, not absolute script pixels. Yoake's existing `DistortTool` maps them through shaped bounds and transforms. Both legacy six-slot P1/P2/P3 and eight-slot P1/P2/P3/P0 forms therefore remain unchanged under ordinary resolution scaling; multiplying them as absolute coordinates would corrupt typesetting. Structural inspection and regression tests must explicitly cover this. Clippos is a script-space translation; clips is a dimensionless percentage. Box padding/radius uses geometry-dependent size rules; positioned gradients contain coordinate bounds plus angles/colors/stops, which must be classified separately. Relative positional operands invert Y at renderer resolution; a resampler must not turn them into absolute positions or add absolute border margins to their deltas. Unsupported/ambiguous geometry must remain byte-preserved with row/tag warnings before confirmation.

The existing structured ASS tokenizer, vector-path validation, immutable background snapshots, atomic editor transactions and document-scoped UI operations are the intended boundaries. Planning must run off the UI thread; publication must fence owner, revision and draft identity. Provide a real source/target/aspect dialog, summary and warnings, cancellation and one-step undo before promotion.
