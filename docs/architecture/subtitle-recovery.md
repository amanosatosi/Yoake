# Subtitle recovery ownership

`AssDocument.CaptureSnapshot` copies mutable record fields on the owning thread and shares immutable raw source strings. Its encapsulated document copy has no native providers, UI controls or editing observers. The background consumer uses the same lossless serializer and encoding/BOM as ordinary Save. Capture does not serialize or join the source on the UI thread.

Each document state owns a publication lease, sequence, in-flight cancellation and successful snapshot stamp. The application dispatcher timer (default 60 seconds, configurable in Options) captures modified committed documents and changed drafts across tabs. Open undo transactions and visual gestures are skipped. Concurrent jobs for the same owner are skipped; a failed write does not advance its successful stamp. Save As/path changes, manual Save, close, disabling autosave and shutdown invalidate the lease and cancel pending work. Publication fencing locks only the final rename, never serialization, compression or flushing; manual Save cannot wait on a lengthy autosave.

One `.yoake-recovery` ZIP contains `document.ass` in its original encoding and a source-generated JSON manifest. The manifest holds a GUID document identity, revision/sequence, provenance, timestamp, checksum, selected row and optional raw field draft. Newlines, incomplete timing and numeric input remain in the draft, never in committed ASS. IME preedit belongs to Avalonia's text presenter and does not enter the bound draft. Numeric input binds its raw text so incomplete values are recoverable. No native state enters recovery metadata.

Writes, hashing, validation, listing and reading run in the background. Publication uses a unique same-directory temporary file, flushes, validates the entire bundle, checks its lease/cancellation and atomically renames. Interrupted temporary files are not recovery entries. A per-store semaphore and a cross-process file lock serialize recovery publication/discard; neither locks normal subtitle files. Recovery cannot overwrite the original file. Checksums, bounded metadata/source sizes and row/field identity checks reject corrupt or excessive data.

Versions are pruned only after replacement publication, retaining ten per document by default. A 512 MiB profile budget rejects new writes with a visible error rather than deleting another document's only recovery. Failed cleanup can leave extra versions; the next successful publication retries cleanup. Successful manual saves and normal shutdown retain bounded recovery history, including unique drafts, until explicit confirmed discard or later pruning. Closing cancels unfinished publication. A crash leaves previously published versions available to the next process.

Recovery opens a new unsaved, dirty tab with its own identity and undo/media state. Provenance is informational and does not become a Save destination. Existing tabs, including invalid drafts, stay intact. Retained drafts are document-owned during recovery-driven tab changes. Invalid recovered values remain editable and cannot commit until validated. Recovery does not delete its selected bundle, and corrupt versions remain visible in the manager without hiding valid versions.
