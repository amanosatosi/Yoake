# Contextual keyboard commands

The default table is generated by `tools/generate_aegisub_hotkeys.py` from the audited, exact Aegisub 3.5.0 shipped common configuration at `43af875ea01e80052cc6c44f24fc8c5258261c6d`. It retains all 120 gestures and eight reference contexts. The compatibility ledger compares every binding with exact 3.2.2 and records the stale frame-split alias migration. `AegisubHotkeyDefaults.MapCommand` translates existing stable Yoake command IDs; additional Yoake gestures are explicit additions to the same profile. Availability of a default binding does not imply its backend is implemented: unregistered commands remain visibly unavailable in Options and reserved for the audited feature work.

`HotkeyProfile` owns defaults plus user overrides, including explicit empty arrays for removed bindings. It validates a complete candidate before replacing the effective resolver or overrides. Multiple gestures per command are supported. A duplicate gesture in the same context is rejected with its existing owner; identical keys across different contexts are valid. Settings persist overrides, with malformed entries ignored independently. Legacy frame-split command names migrate while preserving their context and customized gesture.

The window derives the active context from focused control ancestry. Resolution checks enabled global timing overrides (`Always`, Aegisub's Medusa option) first, then the most specific active context, then `Default`. `Always` is not a fallback when the option is off. Exclusive K-Timing and 39 Mode resolve only their explicitly owned bindings. A resolved disabled/unavailable command does not fall through to another context. Invocation includes the explicit active document ID, including Automation macro commands.

The native editor owns typing, caret navigation, word deletion, clipboard shortcuts and AltGr input. IME preedit and open completion dropdowns retain Enter. Explicit edit-box commit/next, hard newline, formatting and assistant-local keys pass through their proper contexts. Assistant windows must supply their own focused contexts when their workflows are implemented; context enum/table presence alone is not a completed assistant.

Options shows commands and effective bindings by context, captures an actual gesture, and supports add/change/remove/clear, conflict reporting and command/context/all resets. All changes invoke semantic settings commands, persist immediately and update menu display and command adapters on the UI dispatcher. `MenuItem.InputGesture` displays the effective shortcut; `HotKey` is deliberately unused because it would bypass contextual resolution and IME protection. Dynamic Automation menu adapters share the profile without changing the frozen Lua runtime.

Core tests cover exact tables, precedence, migration, conflicts, multiple bindings, removal/resets, invalid entries, persistence and text isolation. Adapter tests cover live shortcut/history/radio metadata. A separate packaged launch sends real routed keys through the shipping focused controls and manipulates the actual Options controls; a second launch reuses the first profile. It supplements the full existing startup verification. Physical OS keyboard layout, AltGr, keypad distinctions and real IME/hardware/DPI remain manual QA.

Audio H and enabled Medusa KP_8 now resolve to the semantic `audio/stop` action rather than its former `video/stop` adapter. This preserves the exact shipped physical/context tables while giving audio stop its playing-only validation. Settings migrate old Audio/Always video-stop override rows once, preserving complete gesture sets and explicit removals and suppressing the old adapter defaults. A persisted marker protects subsequent deliberate video-stop remaps from being migrated again. Audio Escape remains the existing Yoake default. Real Audio Q/W/E/D/R/S/Space/T/B/H routing is exercised separately from native text input and Video D; range previews do not commit drafts.
