# Bundled ASSDraw fork integration

`tool/assdraw` is an application-level launcher, not a document importer, renderer or vector-editor replacement. Discovery checks the explicitly configured absolute `.exe` first, then `ASSDraw3.exe` beside Yoake and in its supported `data` subdirectory. A missing/disappeared configured path falls back to these locations. The command remains discoverable when absent, with the exact required message and a direct route to Options → External tools.

Configuration belongs to the existing source-generated settings/profile system. Portable installations use the existing portable profile resolver; application-data discovery always uses the application directory. Damaged unrelated settings retain the executable member through the existing recovery path. No subtitle/attachment text is used for executable discovery or arguments.

Filesystem discovery and process startup run through the existing background-job service. `ProcessStartInfo.FileName` is explicit, with no concatenated shell command or subtitle-derived arguments, and `UseShellExecute=false`. The local process handle is disposed immediately; its exit and window lifetime remain independent of Yoake. Windows reports invalid/inaccessible executable failures through the central UI-safe command error route. There is no wait for external exit, process-kill-on-document-close behavior or additional playback clock.

The configuration tab and missing-message dialog use real native Avalonia controls and protect IME preedit Enter/Escape. New handlers are unsubscribed on close. Source, draft, selection, media and pending Toshiki state are not committed or changed by launch/configuration.

The portable package includes the user's unchanged `amanosatosi/assdraw` fork at `dda58f913e16743d63ef13bef1beeea0323bd653`, as `ASSDraw3.exe` beside `Yoake.exe`. Normal users need no separate installation or configuration. Custom configuration remains an optional override; the existing Copy ASS clipboard workflow remains the only exchange with subtitle text.

`third_party/assdraw.json` and `ci/build_assdraw.ps1` own a separate CI-only Windows 2022 x64 MSVC build. The supported upstream CMake targets build static wxWidgets 3.2.11/AGG and `/MT`, run upstream tests, resource/import verification and standalone native-window smoke testing. Source identity is verified after Git checkout, the official wxWidgets archive is hash checked, and the executable/source SHA-256 hashes plus actual compiler are recorded in `assdraw-manifest.json`. No existing Yoake decoder/renderer/Automation dependency changes.

The packaging job consumes only that workflow's tested artifact and rejects revision/hash mismatch. A fresh build is available on every run; an expiring artifact is only same-run transport. `ci/verify_assdraw_package.ps1` repeats the exact fork's dependency/resource and standalone-window checks against the packaged bytes. Historical BSD and GPL-2.0-or-later spline notices are retained, not relabelled BSD-only. Full license texts and constituent wx notices accompany the executable. Complete corresponding fork/AGG/wx source archives plus rebuild instructions ship under `sources/assdraw` in the same portable ZIP, satisfying the chosen source-accompaniment distribution route without reliance on a hosting promise.

Packaged Yoake acceptance verifies the actual bundled revision/hash and launches it through Tools without configuration, requiring a responsive independent native window while exact editor/draft/media/pending Toshiki state stays unchanged. The harmless original process fixture remains for repeat-launch, custom paths, missing/error dialogs, keyboard/IME, settings and fallback tests in an isolated owned discovery directory; it never overwrites the bundle. Verification is pending until the full pipeline passes. Actual drawing/coloring/Copy ASS authoring ergonomics and multi-monitor/DPI remain manual QA.
