# Media and analysis timeline

## Independent close, internal video and source extraction

`audio/close` uses `DocumentMedia.WithAudio(null)`. It cancels the Audio open/export/analysis owner, stops the central playback operation, releases only Audio, and clears both cached and presented waveform/spectrum data. Existing pending subtitle markers, draft, selection, history, Video frames and external frame metadata remain document-owned. An uncommitted Audio drag rolls back to its pending checkpoint. Video can immediately seek/play with the existing monotonic clock fallback; opening Audio again restores its independent sample clock. Resource snapshots retain/dispose each track exactly once.

`IVideoProvider` is a source-only boundary implemented by FFMS2 and the deterministic internal dummy provider. `DocumentMedia` retains separate `IDisposable` resource slots with typed Video/Audio access; no native handles or additional clocks escape. Dummy video has the 3.2.2 numeric bounds/defaults, RGB color, 8×8 checkerboard and saved last options, generates no media file and never enters Recent Video. It accepts the same external frame maps and keyframes as decoded video. FFMS2's display aspect comes from the pinned 5.0 SAR fields; opening real video applies its DAR as Custom, as 3.2.2 does. Dummy starts with Default.

All six image commands use `FrameExtraction`: Raw decodes the captured frame index; Full uses that frame plus the existing Mangetsu renderer; Subtitles uses the same renderer on a transparent source-sized host. A capture includes document/provider identity, frame-map object, frame index, mapped timestamp and preview revision. Source ownership is retained throughout background extraction. Changes, close/replacement or superseding work cancel/reject publication; native decode cannot be interrupted mid-call, but obsolete results cannot be copied/saved. Preview composition uses this same mapped-frame timestamp and draft/pending-aware source serialization.

Transparent exports reuse native RGB composition over black, accumulate source-over alpha from premultiplied RGBA tiles in renderer order with clipping, then unpremultiply to straight BGRA. This deliberately differs from normal preview composition, which preserves the host alpha. The private native RGBA layout is shared by production export and provider verification. Avalonia's existing PNG encoder and Windows Bitmap clipboard path preserve RGBA; clipboard data is flushed before releasing the owned bitmap. PNG preparation runs off-thread in a unique sibling temporary file; the UI performs a captured-state/cancellation check immediately before atomic publication. Automatic names match `<stem>_<counter:03>_<frame>.png`, using the video's folder, or the script/home folder for dummy. Existing files are skipped; explicit command destinations (for integrations/tests) have atomic overwrite semantics.

`VideoPresentation` is the common letterbox/aspect transform for image, visual tools and clipboard script coordinates in logical desktop units. Overrides affect presentation only and retain radio state independently per document/tab. They do not edit ASS or create undo operations. Unlike Aegisub's serialized project UI properties, Yoake currently retains aspect state within the document lifetime and resets it when replacing Video; it does not write authoring source solely to persist presentation. Overscan is a saved view preference drawn between the composed image and visual tools, with 3.2.2 wide/narrow safe-area geometry, rounded corners and blue 50% mask. It never enters renderer input or extraction. No pan/zoom/detached-window command or placeholder is introduced.

Video Details snapshots existing source metadata and the active frame map without rescanning native media. It distinguishes source FPS, effective duration, final mapped frame time, decoder/provider and decoded pixel format; external timecodes are identified explicitly. Numeric dialogs guard native IME preedit Enter/Escape and return validated values to semantic commands.

FFMS2 remains the media/index/frame authority. The provider reads frame PTS and track time base from the indexed video track and retains managed timestamps for frame navigation, including VFR. Neighbor stepping uses those timestamps rather than approximating `1/fps`. Native ABI definitions are checked against FFMS2 5.0's pinned `include/ffms.h`. Duration uses the final frame timestamp plus its interval, combined with audio duration.

Playback uses waveOut's played-sample clock when audio exists and a monotonic Stopwatch only for video without audio. The audio display, seek controls, timing commands, video frames and subtitle preview consume the same media time. Selecting or editing a line does not let playback steal grid selection. Play-current-line stops at the line's end; pause and seek cancel the prior playback generation.

FFMS indexing uses its progress callback with an AOT-compatible unmanaged function pointer and a GCHandle containing the cancellation token. The handle is released after synchronous indexing returns. Background job ownership and cancellation belong to the document state; obsolete jobs cannot publish another document's result.

Waveform analysis sequentially reads complete signed audio envelopes in cancellable background chunks. Minimum and maximum remain independent; stereo channels contribute their signed extrema. The overview starts at 1 ms resolution and caps at two million base envelopes for long files; a cached factor-two pyramid keeps scrolling/zooming bounded. Finer viewport analysis goes down to individual sample frames, with eight bounded detail tiles. There is no fixed 10 ms ceiling or UI-thread decoding. Reads release the native audio lock between chunks. The control draws the true upper/lower envelope plus neighboring timings, selection and the central cursor. Click seeks, boundary drags change start/end, Shift+drag moves the range, bottom scrollbar/wheel pan and Ctrl+wheel zooms. Viewport start/span are retained per document. Waveform marker gestures use a document-owned transient checkpoint: release retains pending markers, or publishes one undo operation when Auto-commit is enabled; capture loss/Escape restores the checkpoint without source edits. Generic editor/visual gestures retain their existing rollback-by-default undo transactions.

Display height, waveform amplitude/spectrogram decibel intensity, and playback volume are separate persisted settings. The existing audio/text splitter remains. Playback gain is linear attenuation from 0 to 1 (default 0.8); mute does not overwrite volume. The provider snapshots gain per 20 ms PCM chunk, replaces nonfinite samples with silence and saturates before PCM16 conversion. No additional playback clock or OS mixer dependence is introduced.

FFMS2 also exposes managed frame/keyframe metadata. The custom video ruler navigates frame indices, displays keyframe marks, snaps Shift+click to the nearest keyframe (ties earlier), and steps frames/keyframes with wheel/Shift+wheel. Position labels use exact indexed timestamps and signed offsets from selected subtitle boundaries. Native state remains in Yoake.Native.

Spectrogram analysis is a separate viewport provider producing bounded BGRA tiles. A small radix-2 FFT and Hann window require no dependency or runtime code generation. It is a basic linear-frequency decibel display, with at most four cached viewport tiles. Analysis runs through background jobs with cancellation; scrolling/zooming cancels obsolete requests. Whole-film spectrum arrays are not allocated. Waveform and spectrum share the timing/interaction overlay rather than acquiring separate clocks.

Video decode and Mangetsu rendering run behind a sequential background request gate, with generation checks before/after decode. The caller may supply an owned reusable pixel buffer; the provider fills it before returning. The UI reuses its bitmap for unchanged dimensions and signals Image invalidation after upload. Subtitle source is serialized once per revision, previews are debounced during gestures, and Mangetsu's renderer/font state survives track updates. The existing native API currently replaces a track on document revisions; event-level native patching is not claimed.

Mangetsu's BGRA compositor writes zero to destination alpha within RGBA tiles, even where the source tile is transparent. The host preserves destination alpha before composition and restores it in a finally block, including reported composition failures. A renderer-owned scratch array grows to the largest required pixel count and is reused under the renderer lock; both passes respect row stride and touch only alpha bytes. RGB composition remains Mangetsu's responsibility. Avalonia continues displaying unpremultiplied BGRA, preserving meaningful video alpha instead of forcing opacity. This matches the host-side model in [mpv's Mangetsu integration](https://github.com/amanosatosi/mpv/pull/3).

Packaged provider verification uses actual Mangetsu RGBA tile coverage to distinguish painted pixels, fully transparent pixels inside tiles, and pixels outside every tile. It requires exact destination-alpha preservation, visible RGB changes, unchanged transparent/outside RGB and row padding, using decoded opaque video plus padded synthetic frames with all alpha values, changing dimensions, and steady-state scratch reuse. Native tile inspection stays inside the provider and only runs in verification mode.

GPU-backed frame storage, reusable decoder-native buffers, advanced spectrum scales, persistent media-index caches and audio processing are later provider work. No parallel FFmpeg timeline is added.

While the bounded full-file overview is being generated, the waveform control can request a cancellable visible-range tile. Timing feedback therefore does not have to wait for the long-file overview to finish. Once that overview arrives it supplies ordinary zoom levels; finer zoom requests detail again.

`FrameTiming` derives immutable millisecond boundary data during the existing background media-open job. It has no clock, playback position or provider handle. Editor frame splits use the exact 3.5 START/END midpoint calculations, average-rate extrapolation and ASS half-up centisecond rounding. The provider timestamp origin is retained so these operations agree with Yoake's central time. The frozen Automation 3.2 `AutomationTimecodeView` remains unchanged. If a loaded provider has invalid/unrepresentable boundary timestamps, media remains usable and the failure is reported centrally; only commands requiring these boundaries are disabled.

`video/autoseek` persists whether selecting a line seeks loaded video to its start. Its default retains the existing enabled behavior. Changing the preference itself never seeks or mutates a document; no-video selection behavior remains unchanged. Audio-local hotkey acceptance disables this option explicitly when verifying that navigation does not advance the video frame.

External keyframe files are document-owned metadata, not another timeline. `FfmsMediaSession.SetExternalKeyframes` atomically publishes only a managed immutable list of cuts inside its existing frame bounds; clearing it exposes the original indexed list. The complete external list remains with the document for lossless export and can be loaded before video. The existing timestamps, frame boundary map, provider handles, playback clock and subtitle renderer remain unchanged. Files do not mutate ASS project metadata or imply automatic session reopening.

External timecodes are also document-owned immutable metadata. `TimecodeFile` validates v1/v2 files in cancellable background work; `ExternalTimecodes` preserves explicit timestamps and the assumed/average extrapolation rate and anchor. A prepared `VideoTimecodeMap` contains only the native video's frame count, extending short files while retaining the full intrinsic file for export. `FfmsMediaSession.SetExternalTimecodes` atomically publishes that map and derived duration under its existing video gate. Native decoding uses `FFMS_GetFrame` at the same effective frame index that navigation uses; it must not interpret retimed seconds as original source PTS. Clearing the override restores the original timestamp and information objects without reopening native providers. Audio samples, playback seconds, renderer, document, selection, pending draft and undo survive these metadata changes.

`FrameTiming` uses the intrinsic external rate/anchor for timing and extrapolation. Scene and split validation receive the actual native frame count separately, so a short v1 file does not disable later video frames and a longer external file cannot extend a scene past the video's end. Without video, importing timecodes enables Shift Times frame units but exposes no phantom ruler frames or video-only commands. Pending media indexing and timecode commands cannot publish competing maps; document/media lifetime checks reject stale results. The frozen Automation START algorithm is unchanged: an immutable external-data input constructor supplies the same rate/anchor, and document-host metadata supplies live paths and full external cuts. This is timeline input integration, not a new Lua runtime compatibility profile.

Selected-line audio export snapshots stored subtitle intervals and reads bounded native audio chunks through the existing provider. PCM16 conversion preserves channels/rate and uses no playback gain, extra clock or media reload. Ceiling sample boundaries and clamping match the exact 3.5 exporter, including a valid empty WAV. RIFF overflow and incomplete decoder output are rejected; cancellation is checked during decoding/conversion and before atomic destination replacement. The existing source media cannot be overwritten. Core tests cover geometry/PCM/cancellation/error paths; packaged native verification reopens the exported WAV and checks sample content against the original decoded interval.

`AudioPlaybackPlan` describes ceiling sample boundaries against audio duration, independently of VFR video duration. It adds no clock or provider ownership. The existing central playback activity carries a fixed or following endpoint to WindowsWaveOutStream, which bounds decoded/queued PCM at that endpoint. When a live endpoint shrinks behind submitted buffers, waveOut resets/requeues from its played sample position; endpoint extension can continue queueing. Stop/cancellation observes the worker before releasing its output handles; device failures are reported centrally. The existing media provider and subtitle/draft/undo lifetimes are retained. Core tests cover preview geometry and buffer bounds, native verification covers pre-device cancellation and foreign geometry, and a separate packaged real-input path exercises actual range submission and immediate stop without a fake audio device. Audible output, shrink/extend while listening, driver latency and long-device position wrap remain manual hardware QA.

The primary audio range prioritizes document-owned pending markers, then valid normal draft endpoints and stored timing. Waveform overlay/hits/centering, subtitle preview and existing auditions share it. Marker movement does not seek, reopen providers, create source history or create a playback clock. Following auditions receive the existing endpoint update; capture loss restores that endpoint. Commit rebases the same draft's endpoints and publishes the existing lossless timing plan. Normal timing navigation retains markers per event and uses the existing intentional selection/autoseek policy; a boundary no-op preserves selection. Source edits cancel obsolete gestures and invalidate conflicting markers. Zero-ended default-next destinations can retain a nonzero stored start until their valid staged range is explicitly committed.

Yoake retains synchronized video preview while auditioning audio through this single timeline, as its previous line playback did. Exact Aegisub stops its separate video controller and advances an independent audio cursor. Yoake stops the previous playback activity before beginning the requested audio interval, but does not introduce a second cursor/clock or display a frozen video image against an advancing frame ruler. The preview range is bounded by audio samples even when external VFR timecodes extend the video duration.


Independent media ownership: `DocumentMedia` is a document-owned immutable resource snapshot, not another editor/session or playback clock. `MediaProviderOwnership<T>` retains separate video/audio resources when producing a replacement snapshot and disposes each resource exactly once on final release. FFMS2 indexes a combined open once, then transfers its native handles into separate gated `FfmsMediaSession` owners without reopening them. Dedicated Video Open creates only a video decoder; dedicated Audio Open creates only an audio decoder with the existing video-relative delay policy. The legacy combined Open remains available intentionally.

Video replacement prepares native frame timing and external timecodes/keyframes off-thread before publication. Failure, cancellation, superseded indexing, closed/replaced document ownership, or obsolete external metadata cannot publish. Publication retains the latest independent audio provider, waveform/viewport, editor, draft, pending timing, selection, undo and external metadata. Video Close releases only video. Audio replacement retains video and its frame map. Video playback stops when its video is replaced/closed; explicit Audio auditions can continue on the same retained audio/sample clock. Peaks, spectrum, detail analysis and audio export validate the actual audio resource identity rather than the combined snapshot, so video changes do not discard audio state. Frame/render requests retain the existing generation checks. No new native dependency or Automation runtime semantics are introduced; only the host's existing path metadata follows the corresponding provider.

Video and Play Line end at the video endpoint even when audio is longer. The verified central clock continues silently beyond shorter audio EOF; explicit Audio auditions keep their range/sample endpoint semantics. Closing/replacing a provider creates no subtitle undo operation. Native disposal is performed off the UI thread when releasing a live document snapshot.
